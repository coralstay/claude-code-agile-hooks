## Q-1 `config_guard.py`의 스크립트 파일 경유 우회 차단 범위

- **무엇이 미정인가** — 보호 경로(사용자 Claude Code 설정 · 훅 디렉토리 · 프로젝트 설정 · MCP · 플러그인 매니페스트)를 고치는 코드를 스크립트 파일로 먼저 Write한 뒤 `python3 x.py`처럼 실행하면 통과한다. `config_guard.py`는 Bash 명령 문자열과 `python -c` · stdin heredoc 코드만 검사하고, Write/Edit는 대상 경로만 보기 때문이다. 후보는 다섯이다 — ① 인터프리터가 실행하는 스크립트 파일을 읽어 같은 규칙 적용(경로를 해석할 수 없으면 차단) ② 실행 가능한 스크립트를 Write/Edit할 때 내용에 보호 경로 + 쓰기 연산이 있으면 차단 ③ 보호 경로 해시를 세션 시작 시 기록하고 PostToolUse마다 비교하는 무결성 감시 ④ 보호 경로가 쓰기 대상이 아니라 치환 문자열 · heredoc 본문에 언급만 된 경우의 오탐 줄이기 ⑤ CLAUDE.md.snippet에 "가드에 막히면 우회하지 말고 보고" 규칙.
- **왜 못 정하나** — ① · ②는 문자열 매칭의 연장이라 인터프리터 · 언어 목록이 끝나지 않고(1.02 P-4), 오탐이 늘면 우회 동기가 커진다. 실제로 발견된 우회는 오탐(저장소 파일의 경로 문자열 치환)을 피하려다 생겼다 — 차단 강화(①②)와 오탐 감소(④)가 서로 당긴다. ③은 문자열로 못 잡는 경로까지 덮지만 사후 탐지다. 어느 조합이 범위인지는 draft 승격 때 사람이 정한다(1.02 P-3).
- **무엇이 정해주나** — DRAFT-7 승격 시의 범위 확정. 수용 기준 초안은 "스크립트 생성 → 실행 시나리오가 막힌다", "저장소 파일 안 경로 문자열 치환은 통과한다", "커버리지 100% 유지"다.

## Q-2 `pre_compact_backup.py`의 같은 초 덮어쓰기

- **무엇이 미정인가** — 백업 파일 이름이 `<session_id>-<UTC %Y%m%dT%H%M%SZ>.jsonl`이라 같은 세션에서 1초 안에 PreCompact가 두 번 일어나면 뒤 백업이 앞 백업을 덮어써 transcript 사본 하나를 잃는다. 후보는 마이크로초까지 넣기, 이름이 있으면 `-1` · `-2` 접미사, 배타 생성(`x` 모드)으로 충돌 감지다.
- **왜 못 정하나** — 세 후보 모두 동작은 고치지만 백업 파일 이름 형식이 바뀌는 정도가 다르고, 백업을 읽는 쪽(사람 · 도구)의 이름 규칙 의존이 아직 정리되지 않았다(3.04 골격). 훅은 압축을 절대 막지 않아야 하므로 충돌 시 실패하는 선택지는 쓸 수 없다.
- **무엇이 정해주나** — DRAFT-5 승격 시의 이름 규칙 선택과 같은 초 두 번 백업 재현 테스트.

## Q-3 `session_id` 경로 조작 방어

- **무엇이 미정인가** — `pre_compact_backup.py`는 입력의 `session_id`를 그대로 파일 이름에 넣어, `/`나 `..`가 들어 있으면 백업 디렉토리 밖에 쓸 수 있다. 같은 패턴은 `session_id`로 경로를 만드는 다른 훅에도 있다 — `session_logger.py` · `standup_autopilot.py` · `dead_end_registry.py` · `pr_provenance_stamp.py`는 그대로 쓰고, `context_flags.py` · `pipeline_trace.py`는 basename만 남긴다. 후보는 `[A-Za-z0-9_-]`만 남기는 정규화, 최종 경로가 대상 디렉토리 안인지 확인한 뒤에만 쓰기다.
- **왜 못 정하나** — 고치는 방식을 훅마다 따로 정하면 같은 결함이 사본마다 다르게 고쳐진다. 1.02 P-2 때문에 공용 함수로 묶을 수 없으므로, 같은 정규화 함수를 복사하고 REGISTRY(1.02 P-5)에 올릴지, 훅마다 다른 수단을 허용할지를 먼저 정해야 한다.
- **무엇이 정해주나** — DRAFT-6 승격 시의 방식 선택과 점검 범위(위 6개 훅) 확정.

## Q-4 syscall 레벨 샌드박스 레이어

- **무엇이 미정인가** — 문자열 매칭이 구조적으로 못 막는 경로(인코딩 트릭 · 간접 실행 · 스크립트 경유)를 커널 레벨 강제로 덮는 별도 레이어를 만들 것인가.
- **왜 못 정하나** — 이 컴포넌트 안에서는 구현할 수 없다(1.02 P-4). seccomp-bpf · eBPF · Landlock · bubblewrap 같은 기술은 대부분 Linux 전용이라 macOS에서 무엇을 쓸 수 있는지 조사되지 않았고, Claude Code 자체 샌드박스 · `permissions.deny`만으로 충분한지도 판단되지 않았다.
- **무엇이 정해주나** — DRAFT-2 탐색. 별도 프로젝트로 분리할 가치가 있다고 판단되면 이 컴포넌트가 아니라 새 컴포넌트로 최상위 문서에 올린다.

## Q-5 복붙 함수 drift의 codegen 전환

- **무엇이 미정인가** — REGISTRY 사후 검증을 하나의 소스에서 N개 훅 파일로 생성하고 CI가 재생성 후 diff로 검증하는 방식(Kubernetes `update-codegen` · `verify-codegen` 패턴)으로 바꿀 것인가.
- **왜 못 정하나** — 생성된 파일이 런타임에는 여전히 독립형이라 1.02 P-2와 충돌하지 않는다는 논리는 세울 수 있지만, 아키텍처를 크게 바꾸는 일이고 필요성(REGISTRY 증가 · drift 재발)이 아직 쌓이지 않았다(decision-2).
- **무엇이 정해주나** — DRAFT-1 탐색과 REGISTRY 사각지대 · drift 재발 기록.

## Q-6 backlog.md 미사용 프로젝트의 훅 구성

- **무엇이 미정인가** — backlog.md를 쓰지 않는 프로젝트에서 backlog.md 전용 훅 7개가 조용히 통과(no-op)하는 지금 방식을 유지할지, 애초에 등록하지 않을지.
- **왜 못 정하나** — 등록하지 않으려면 프로젝트별 등록 · 해제가 필요하고, 그것은 라우터 · dispatcher 도입(decision-3에서 거절)과 가까워진다. 그 조건이 언제 생기는지 아직 구체화되지 않았다.
- **무엇이 정해주나** — DRAFT-3 검토.

## Q-7 `hooks/` 디렉토리 구조

- **무엇이 미정인가** — 지금 평평한 `hooks/`를 성격별 서브디렉토리(3.01 §2의 세 성격이 자연스러운 후보)로 나눌 것인가.
- **왜 못 정하나** — import 관계가 그대로면 1.02 P-2 위반은 아니지만, `install.sh` · `settings.hooks.json` · 계약 테스트의 경로 참조가 얼마나 바뀌는지 파악되지 않았다.
- **무엇이 정해주나** — DRAFT-4 검토.

## Q-8 AC 밖 작업 발견의 강제 수단

- **무엇이 미정인가** — 에이전트가 AC 밖 작업을 발견했을 때 범위를 조용히 넓히지 않고 사람에게 확인하게 하는 것(RAIL-012)을 무엇으로 강제하는가. 지금은 CLAUDE.md의 약속뿐이다.
- **왜 못 정하나** — 스코프 판단은 문자열로 검증할 수 없다. `prompt` · `agent` 타입 훅으로 LLM 판단을 걸 수는 있지만 오탐 · 누락을 검증하지 않았다. `dead_end_registry.py`는 되돌린 접근의 재시도만 다루고 스코프 이탈과는 별개다.
- **무엇이 정해주나** — LLM 판단형 훅의 실측. 최상위 Q-19와 같은 항목이므로 결정은 최상위와 함께 남긴다.

## Q-9 AC 체크 전 증거 확인

- **무엇이 미정인가** — `--check-ac` 직전에 해당 AC의 테스트 증거가 있는지 확인하는 구조.
- **왜 못 정하나** — PostToolUse로 테스트 결과를 상태 파일에 남기고 PreToolUse가 확인하는 2단 구조가 필요한데, AC와 테스트를 잇는 표기가 정해지지 않았다(최상위 Q-14의 `ac_id` 표기와 맞물린다).
- **무엇이 정해주나** — AC ↔ 테스트 연결 표기 확정과 상태 파일 스키마(3.04).

## Q-10 역할 식별 방식

- **무엇이 미정인가** — Implementer만 writer로 두는 역할 인식 쓰기 제한(RAIL-010)에서, 훅이 지금 세션의 역할을 무엇으로 아는가.
- **왜 못 정하나** — 역할 프로세스를 띄우는 쪽(agent-orchestrator)의 격리 방식(워크트리 · 환경변수 · 파일 권한)이 정해지지 않았다.
- **무엇이 정해주나** — 최상위 Q-5.

## Q-11 세션 마비 대응과 훅 레이턴시

- **무엇이 미정인가** — 훅이 에이전트가 스스로 해소할 수 없는 조건으로 필수 액션(Stop 등)을 반복 차단할 때의 탈출구(훅 단위 kill switch, 재시도 상한), 그리고 도구 호출당 훅 기동 비용의 상한. Bash 한 번에 PreToolUse 훅이 최대 14개 뜬다.
- **왜 못 정하나** — 세션 마비는 2026-10-03에 재현됐지만, 다른 차단 훅 가운데 같은 조건으로 막는 곳이 있는지 점검하지 않았다. 레이턴시는 계측하지 않았다. kill switch는 우회 수단이 될 수 있어 1.02 P-1과 함께 따져야 한다.
- **무엇이 정해주나** — 훅별 실행 시간 로깅과 해소 불가 조건 점검.

## Q-12 관측 로그 보존 정책

- **무엇이 미정인가** — 기록 · 관측 훅이 사용자 홈의 hooks-logs 아래에 쌓는 JSONL · 마크다운 · 세션별 JSON의 로테이션 · 정리.
- **왜 못 정하나** — 어떤 로그를 누가 얼마나 오래 읽는지(사람의 회고, 다른 훅의 소비) 정리되지 않았다.
- **무엇이 정해주나** — 적재량 실측과 소비자 요구.

## Q-13 상태 이름 하드코딩

- **무엇이 미정인가** — 절차 강제 훅이 `In Progress`를 하드코딩한다. 프로젝트가 `backlog config`로 상태명을 바꾸면 오작동할 수 있다.
- **왜 못 정하나** — 최상위 설계는 저장 상태 어휘를 To Do · In Progress · Done 세 값으로 고정하는 방향이라(최상위 1.03 비목표) 설정에서 읽을 필요가 실제로 생기는지 불분명하다.
- **무엇이 정해주나** — 상태명을 바꾼 프로젝트에서의 실제 요구. 생기지 않으면 고정을 명세로 올린다.

## Q-14 `pipeline_trace.py`의 payload 실측

- **무엇이 미정인가** — 거부된 `ExitPlanMode`가 모든 거부 방식에서 이벤트를 남기지 않는지, `permission_mode == "auto"`가 대화형 · PostToolUse payload에 실제로 오는지, 서브에이전트 도구 호출이 부모 `session_id`로 오는지.
- **왜 못 정하나** — Claude Code 동작이라 실측으로만 알 수 있고, 관측된 거부 67건은 거부 방식별로 나눠 보지 않았다.
- **무엇이 정해주나** — 설치 후 파이프라인 상태 파일을 모은 실측. 계획 없는 편집 경고의 오탐 비율도 함께 본다.
