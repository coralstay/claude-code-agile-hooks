# 3.01 시스템 구성

claude-code-agile-hooks는 Claude Code 훅 이벤트에 등록된 독립 Python 스크립트 32개이고, 각 훅은 ① 절차 강제 · ② 품질 · 안전 게이트 · ③ 기록 · 관측 중 정확히 한 성격에 속한다.

## §1 구성 요소

| 요소 | 위치 | 책임 |
| --- | --- | --- |
| 훅 32개 | `hooks/*.py`(테스트 `hooks/test_*.py` 제외) | 이벤트마다 payload를 읽고 허용 · 차단 · 맥락 주입 · 기록 중 하나를 한다. 서로 import하지 않는다(1.02 P-2) |
| 등록 정의 | `settings.hooks.json` | 이벤트 · matcher · `if` 필터별 훅 등록 50건 |
| 설치 | `install.sh` · `scripts/merge_settings.py` | 훅을 사용자 홈의 Claude Code 훅 디렉토리에 복사하고, 사용자 설정에 추가 전용으로 병합한다 |
| 지침 블록 | `CLAUDE.md.snippet` | 훅이 강제하지 못하는 부분(스코프 판단 등)을 에이전트에게 알리는 CLAUDE.md 마커 블록 |
| 프로젝트 설정 | 대상 저장소의 `.claude-code-agile-hooks.json`(옛 `.claude-rails.json`) | `testCommand` · `coverageCommand` |
| 계약 테스트 | `hooks/test_hook_registration_contract.py` · `hooks/test_hook_runtime_contract.py` | `if` 필터가 검사 대상을 가리지 않는지, 등록된 모든 훅이 빈 입력 · 깨진 JSON · 정상 입력에서 정해진 종료 코드를 내는지 |

backlog.md 전용 여부는 성격과 다른 축이다. backlog.md 전용 훅 7개(`backlog/config.yml`이 있는 프로젝트에서만
동작)는 모두 ① 절차 강제에 있고, ①의 나머지 하나(`auto_stage.py`)와 ② · ③ 전부는 프로젝트 종류와 무관하게
항상 켜진다.

## §2 훅의 세 가지 성격

| 성격 | 하는 일 | 대응하는 관행 | 막는가 | 최상위 요구사항 |
| --- | --- | --- | --- | --- |
| ① 절차 강제 | 정해진 작업 순서를 벗어난 액션을 막는다 | 애자일(스크럼 · 칸반) 의식 | 막는다(브리핑 · 자동 스테이징 제외) | RAIL-001 ~ RAIL-005 · RAIL-007 · RAIL-008 · RAIL-011 · RAIL-015 |
| ② 품질 · 안전 게이트 | 순서와 무관하게, 품질을 거짓으로 만들거나 되돌릴 수 없는 피해를 내는 액션을 막는다 | CI 품질 게이트 · DevSecOps | 막는다(자동 허용 · 설정 감시 기본값 제외) | RAIL-006 · RAIL-013 · NFR-016 · RAIL-016 · RAIL-017 · RAIL-018 |
| ③ 기록 · 관측 | 막지 않고 남긴다. 사람이 나중에 읽을 자료를 만든다 | 스탠드업 · 회고 · 기술 부채 기록 | 막지 않는다 | RAIL-014 |

RAIL-015 ~ RAIL-018은 이 저장소의 분류에서 드러나 최상위 2.03에 올린 요구사항이다 — 세션 시작 브리핑(`session_start.py`), 적대적 지시가 든 지침 파일 감사(`instructions_audit.py`), 하네스 예약 태그 위조 방지(`reserved_tag_guard.py`), 권한 자동 허용 범위의 제한(`permission_auto_allow.py`).

분류 기준은 "그 훅이 실패했을 때 무엇이 깨지는가"다. ①이 빠지면 절차가 깨지고, ②가 빠지면 품질 신호나 환경이
깨지고, ③이 빠지면 기록만 비고 작업은 그대로 진행된다.

![Claude Code 훅 이벤트 × 훅의 세 가지 성격](../diagrams/01-three-natures.svg)

간선 하나가 `settings.hooks.json`의 등록 하나다. 굵은 실선은 막을 수 있는 등록, 점선은 기록 · 맥락 주입 ·
경고만 하는 등록이다.

### ① 절차 강제 — 애자일 의식 ↔ 훅

| 애자일 의식 | 이 컴포넌트에서의 형태 | 훅 | 이벤트 | 사람의 몫 |
| --- | --- | --- | --- | --- |
| 데일리 스크럼 전 보드 확인(브리핑) | 세션이 시작되면 워크플로 가이드와 백로그 무결성 이슈를 맥락에 넣는다 | `session_start.py` | SessionStart | 요청을 보낸다 |
| 백로그 정제 · PO 승인 | 새 작업은 draft로만 들어오고, 사람이 승인한 뒤 promote로만 태스크가 된다. draft 생성 · 승격은 각자 단독 커밋이어야 한다 | `require_draft_first.py` · `backlog_commit_scope.py` | PreToolUse(Bash) | **draft 승인** (판단 지점 ①) |
| 당겨오기(칸반 pull) | In Progress 태스크가 있고 이번 세션에 `backlog task view`로 읽은 뒤에만 편집할 수 있다 | `require_active_task.py` | PreToolUse(Edit\|Write) | — |
| 티켓 브랜치 · CI 게이트 | `task/<ID>` 브랜치에서만, `testCommand`가 통과해야 커밋된다. 수정한 파일은 자동으로 스테이징되고, 미커밋 변경을 남긴 채 턴을 끝낼 수 없다 | `pre_commit_check.py` · `auto_stage.py` · `block_stop_if_dirty.py` | PreToolUse(Bash) · PostToolUse(Edit\|Write) · Stop | — |
| Definition of Done | 태스크가 Done이고 final summary가 있어야 push된다 | `pre_push_check.py` | PreToolUse(Bash) | **push · 병합 전 리뷰** (판단 지점 ②) |

| 영역 | 막는 것 | 훅 |
| --- | --- | --- |
| CI 품질 게이트 | 커버리지 미달 push | `pre_push_coverage_check.py` |
| CI 품질 게이트 | 테스트 삭제 · skip/xfail로 만든 가짜 그린 | `protect_tests.py` |
| CI 품질 게이트 | 훅 저장소 자신의 복붙 함수 drift | `dedup_drift_guard.py` |
| DevSecOps — 비밀 | 시크릿 파일 열람 · 수정 · 외부 모델 CLI로 유출 | `protect_secrets.py` |
| DevSecOps — 파괴적 명령 | 파국적 셸 명령, 대소문자 무시 파일시스템의 오삭제, main 직접 push · 보호 브랜치 삭제 · 파괴적 `gh` | `block_dangerous_commands.py` · `case_insensitive_guard.py` · `pre_git_safety_check.py` |
| DevSecOps — 가드 자체 보호 | 에이전트의 훅 · 설정 변조, 세션 밖에서 들어온 설정 변경, 적대적 지시가 든 지침 파일 | `config_guard.py` · `config_watch.py` · `instructions_audit.py` |
| DevSecOps — 신뢰 경계 | 권한 자동 승인 범위를 읽기 전용으로 제한, 하네스 예약 태그 위조 | `permission_auto_allow.py` · `reserved_tag_guard.py` |

### ③ 기록 · 관측

| 관행 | 남기는 것 | 훅 |
| --- | --- | --- |
| 스탠드업 | 세션 로그, 일일 스탠드업 파일과 전날 미해결 항목 재주입, recap 영구 보관 | `session_logger.py` · `standup_autopilot.py` · `recap_archive.py` |
| 회고 | 되돌린 접근 · 규칙 준수 스코어카드 · 모델별 실패율과 토큰 · 컨텍스트 소비 · 작업 파이프라인 흔적 | `dead_end_registry.py` · `dead_rules_audit.py` · `nerf_receipts.py` · `context_hogs.py` · `pipeline_trace.py` |
| 기술 부채 | TODO/FIXME/HACK의 나이에 따른 부채 가격 | `bounty_board.py` |
| 맥락 보존 · 감사 추적 | 압축 직전 transcript 백업, 세션 상태 플래그, PR 본문의 출처 영수증 | `pre_compact_backup.py` · `context_flags.py` · `pr_provenance_stamp.py` |

## §3 훅 분류표

32개 전부를 성격 하나에 넣는다. 이벤트(matcher)는 `settings.hooks.json` 등록을, 근거는 각 훅의 모듈 docstring을 따른다.

| # | 훅 | 이벤트(matcher) | 성격 | 근거(docstring) |
| --- | --- | --- | --- | --- |
| 1 | `session_start.py` | SessionStart | ① | backlog.md 프로젝트면 공식 워크플로 가이드로 브리핑하고 무결성 이슈를 띄운다. 막을 수 없고 맥락 주입만 한다 |
| 2 | `require_draft_first.py` | PreToolUse(Bash) | ① | 새 작업은 draft로 들어와 사용자 검토 후 promote로만 태스크가 된다. 명령 위치의 `backlog task create`를 거부한다 |
| 3 | `backlog_commit_scope.py` | PreToolUse(Bash) | ① | draft 생성 · 승격이 각자 단독 커밋이 되도록, 다른 변경이 섞인 커밋을 거부한다 |
| 4 | `require_active_task.py` | PreToolUse(Edit\|Write) | ① | In Progress 태스크가 있고 이번 세션에 `backlog task view`로 읽은 뒤에만 편집을 허용한다 |
| 5 | `pre_commit_check.py` | PreToolUse(Bash) | ① | 커밋은 `task/<ID>` 브랜치에서, 프로젝트가 설정했으면 테스트 통과 후에만 한다 |
| 6 | `auto_stage.py` | PostToolUse(Edit\|Write) | ① | Claude가 수정한 파일을 자동으로 `git add`해 `git status`가 Claude가 만진 것을 정확히 보여 주게 한다 |
| 7 | `block_stop_if_dirty.py` | Stop | ① | 태스크가 In Progress인 동안 미커밋 변경을 남긴 채 턴을 끝내지 못하게 해 작은 커밋 루프를 끝까지 돌게 한다 |
| 8 | `pre_push_check.py` | PreToolUse(Bash) | ① | `task/<ID>` 브랜치는 그 태스크가 Done이고 final summary가 있을 때만 push한다 |
| 9 | `pre_push_coverage_check.py` | PreToolUse(Bash) | ② | `coverageCommand`를 push 전에 돌려 실측 보고를 보이고, 명령이 실패하면 push를 막는다. 시도마다 coverage-log에 남긴다 |
| 10 | `protect_tests.py` | PreToolUse(Bash\|Edit\|Write) | ② | 테스트 파일 삭제 · 이름 바꾸기 · skip/xfail로 테스트를 끄는 "가짜 그린"을 막는다 |
| 11 | `dedup_drift_guard.py` | PreToolUse(Bash, `if: Bash(git *)`) | ② | REGISTRY에 등록된 복붙 함수의 사본이 어긋나면 `git commit`을 막는다 |
| 12 | `protect_secrets.py` | PreToolUse(Read\|Edit\|Write\|Bash) | ② | 시크릿 파일(.env · SSH 키 · 클라우드 자격 증명 · 키스토어)의 열람 · 수정 · 유출을 막는다 |
| 13 | `block_dangerous_commands.py` | PreToolUse(Bash) | ② | 파국적 · 고위험 셸 명령을 실행 전에 막는다. `HOOK_SAFETY_LEVEL`로 규칙 세트를 고른다 |
| 14 | `case_insensitive_guard.py` | PreToolUse(Bash) | ② | 대소문자만 다른 형제 경로가 있으면 `rm -rf`류 삭제를 막는다 |
| 15 | `pre_git_safety_check.py` | PreToolUse(Bash) | ② | main/master 직접 push, 보호 브랜치 삭제, 파괴적 `gh` 작업을 막는다 |
| 16 | `config_guard.py` | PreToolUse(Bash\|Edit\|Write) | ② | 에이전트가 자기 가드레일 설정(훅 · 설정 · MCP · 플러그인 매니페스트)을 고치거나 새로 만드는 것을 막는다 |
| 17 | `config_watch.py` | ConfigChange(user · project · local · policy settings · skills) | ② | 세션 중의 설정 변경을 드러내고, `CONFIG_WATCH_BLOCK=true`면 막는다. 에이전트 밖에서 들어온 변경을 다룬다 |
| 18 | `instructions_audit.py` | InstructionsLoaded · UserPromptSubmit · PreToolUse(전체) | ② | 로드되는 CLAUDE.md · 규칙 파일에서 숨은 · 적대적 지시를 찾으면 세션을 잠근다 |
| 19 | `permission_auto_allow.py` | PermissionRequest | ② | 읽기 전용 도구 · 명령만 자동 허용하고, 그 밖은 일반 권한 프롬프트에 넘긴다. 거부하지 않는다 |
| 20 | `reserved_tag_guard.py` | Stop | ② | 어시스턴트 응답에 하네스 예약 태그가 있으면 턴 종료를 막아, "사용자가 실행했다"는 신뢰 경계의 위조를 막는다 |
| 21 | `session_logger.py` | SessionStart · UserPromptSubmit · PostToolUse · SessionEnd | ③ | 세션의 cwd · 브랜치 · 프롬프트 · 만진 파일 · 실행한 명령을 JSONL로 남긴다 |
| 22 | `standup_autopilot.py` | SessionStart · Stop · SessionEnd | ③ | 실제로 한 일로 일일 스탠드업을 쓰고, 다음 SessionStart에 전날 미해결 항목을 다시 넣는다 |
| 23 | `recap_archive.py` | SessionStart · SessionEnd | ③ | transcript가 지워진 뒤에도 남도록 세션 recap(away_summary)을 append-only 아카이브에 복사한다 |
| 24 | `dead_end_registry.py` | UserPromptSubmit · PreToolUse(Edit\|Write) | ③ | 되돌린 접근을 이유와 함께 기억하고, 같은 막다른 길을 다시 시도하면 경고한다(막지 않는다) |
| 25 | `dead_rules_audit.py` | SessionStart · PostToolUse(Edit\|Write) · SessionEnd | ③ | CLAUDE.md 규칙 준수 스코어카드를 매기고, 늘 무시되는 규칙을 결정적 훅으로 올릴 후보로 표시한다 |
| 26 | `nerf_receipts.py` | PostToolUse · PostToolUseFailure · Stop | ③ | 모델 버전별 실패율 · 편집 churn · 태스크당 토큰을 기록한다 |
| 27 | `context_hogs.py` | PostToolUse(Read\|Grep\|Glob\|Bash) | ③ | 도구 결과의 대략적 토큰 비용을 파일별로 모은 컨텍스트 소비 리더보드 |
| 28 | `pipeline_trace.py` | UserPromptSubmit · PostToolUse · Stop | ③ | plan mode → 승인 → draft → 커밋 → 승격 파이프라인을 세션별로 관측 · 기록하고, 계획 없이 편집한 세션에 Stop에서 한 번 경고한다(막지 않는다) |
| 29 | `bounty_board.py` | SessionStart · PostToolUse(Edit\|Write) | ③ | TODO/FIXME/HACK 부채를 나이에 따라 오르는 XP 현상금으로 매긴다 |
| 30 | `pre_compact_backup.py` | PreCompact | ③ | 압축이 맥락을 버리기 직전에 transcript 전체를 백업한다. 항상 0으로 끝나고 압축을 막지 않는다 |
| 31 | `context_flags.py` | SessionStart · PreCompact · Stop | ③ | 자기 이벤트 payload에 없는 세션 상태(압축 여부 · 병렬 세션 등)를 다른 훅이 읽도록 세션별 플래그 파일을 남긴다 |
| 32 | `pr_provenance_stamp.py` | PreToolUse(Bash, `if: Bash(gh pr create*)`) | ③ | `gh pr create` 때 PR 본문에 출처 영수증(프롬프트 수 · 실행한 테스트 · 에이전트가 쓴 파일 수)을 붙인다 |

합계: ① 8 · ② 12 · ③ 12 = 32. `ls hooks/*.py`에서 `test_*`를 뺀 목록과 한 줄씩 대조했다.

### 두 성격에 걸친 훅 — 왜 이 성격인가

| 훅 | 걸친 성격 | 고른 성격과 이유 |
| --- | --- | --- |
| `session_start.py` | ① · ③ | 막지 않지만 남기지도 않는다. 하는 일은 절차의 첫 단계(브리핑)를 맥락에 넣는 것이므로 ① |
| `auto_stage.py` | ① · ③ | backlog.md 전용이 아닌 범용 훅이고 막지도 않는다. 그러나 존재 이유가 "작은 커밋 루프"의 스테이징 단계를 자동화하는 것이고, `block_stop_if_dirty.py`와 짝을 이루므로 ① |
| `pre_commit_check.py` | ① · ② | `testCommand` 실행은 품질 게이트지만, 이 훅의 일차 규칙은 "커밋은 티켓 브랜치에서"이고 테스트 실행은 프로젝트가 켤 때만 붙는다. 절차(CI 게이트 단계)로 보아 ① |
| `pre_push_coverage_check.py` | ② · ③ | coverage-log에 기록하지만, 실패하면 push를 막는다. 막는 쪽이 본질이므로 ② |
| `pre_git_safety_check.py` | ① · ② | main 직접 push 금지는 사람 판단 지점(push · 병합 전 리뷰)을 지키는 절차이기도 하지만, 태스크 · backlog.md와 무관하게 되돌릴 수 없는 git · gh 작업 전반을 막으므로 ② |
| `dedup_drift_guard.py` | ① · ② | 커밋을 막지만 지키는 대상이 작업 순서가 아니라 이 저장소 코드의 일관성(1.02 P-5)이므로 ② |
