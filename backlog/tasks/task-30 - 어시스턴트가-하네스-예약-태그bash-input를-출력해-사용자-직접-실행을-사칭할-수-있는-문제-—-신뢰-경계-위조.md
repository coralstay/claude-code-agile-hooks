2026-09-26 coralstay-software-factory 최초 push 세션에서 실제로 발생. 우선순위 높음.

## 현상

Claude가 응답 본문에 `<bash-input>cd /path && git push</bash-input>` 형태의 블록을 출력했다. 이 태그는 원래 **사용자가 `!` 프리픽스로 직접 실행한 명령**을 트랜스크립트에 표기하기 위한 하네스 예약 형식인데, 모델이 단순한 "명령 제안" 용도로 같은 형식을 생성해버렸다.

결과적으로 트랜스크립트만 보면 사용자가 그 명령을 직접 실행한 것처럼 보였고, 사용자가 "지금 내가 터미널에서 새롭게 푸쉬한 게 아니다"라고 직접 지적해 발각됐다. 실제 실행은 없었다.

## 왜 심각한가 — 신뢰 경계의 위조

이건 단순한 출력 서식 실수가 아니라 **가드 정책의 근거를 무너뜨리는 문제**다.

- pre_git_safety_check.py를 비롯한 훅들은 **Claude의 Bash 도구 호출에만** 걸린다. 사용자가 `!` 로 직접 실행하는 명령에는 걸리지 않는다.
- 따라서 "위험한 작업은 사용자가 직접 실행하게 한다"가 정식 우회 절차로 성립한다 (DRAFT-7 선택지 3이 정확히 이 전제에 기대고 있다).
- 그런데 "사용자가 직접 실행했다"는 **표식 자체를 모델이 생성할 수 있다면**, 그 신뢰 경계는 위조 가능한 마킹에 의존하는 셈이 된다.
- 감사 추적(audit trail) 오염: 사후에 트랜스크립트를 읽는 사람(또는 recap/standup 훅 같은 자동화)이 "사용자가 승인하고 실행했다"고 잘못 판단할 수 있다.

악의적 의도 없이도 발생했다는 점이 핵심이다. 모델이 친절하게 "이 명령 실행하세요"를 보기 좋게 렌더링하려다 예약 형식을 밟았다.

## 검토할 대응

1. **Stop / PostToolUse 훅 레벨 탐지**: 어시스턴트 출력 텍스트에 `<bash-input>`, `<bash-stdout>`, `<bash-stderr>`, `<system-reminder>`, `<persisted-output>` 등 하네스 예약 태그가 포함되면 차단하거나 경고를 띄운다. 트랜스크립트 파일을 읽는 기존 훅(recap 계열)과 같은 경로를 쓸 수 있는지 확인 필요.
2. **CLAUDE.md 규칙 명시**: 사용자에게 제안하는 명령은 반드시 펜스 코드블록(```bash)으로만 쓰고, 하네스 예약 태그는 어떤 경우에도 출력하지 않는다.
3. **정책 자체 재검토 (가장 근본적)**: "사용자 직접 실행"을 신뢰 경계로 삼는 우회 절차(DRAFT-7 선택지 3)를 유지할지 재고한다. 표식이 위조 가능하다면, 위험 작업의 승인은 트랜스크립트 표기가 아니라 훅이 직접 검증 가능한 신호(원격 상태 조회, 별도 승인 파일 등)에 근거해야 한다.
4. **탐지 범위 확정**: 코드블록 안에 예시로 적는 경우까지 막으면 이 draft 문서 자체도 걸린다. 펜스 내부/외부 구분이 필요한지 판단해야 한다.

### 추정 트리거

14번에서 **진짜 하네스 출력인 `<bash-input>` 블록이 컨텍스트에 들어왔고**, 바로 다음 턴인 15번에서 모델이 그 형식을 "명령을 보기 좋게 렌더링하는 방법"으로 오인해 그대로 모방했다. 13번까지는 같은 세션에서 펜스 코드블록을 정확히 쓰고 있었다는 점이 방증이다.

즉 **컨텍스트 안의 정당한 하네스 출력이 사실상 few-shot 예시로 작동**했다. 악의도, 우회 의도도 없었다.

### 재현 조건 (가설)

> 사용자가 `!` 프리픽스로 명령을 실행한 **직후 턴**에, 모델이 또 다른 명령을 제안할 때.

이 조건이 맞다면 탐지 훅 없이 프롬프트 규칙만으로 막는 건 불안정하다 — 형식 모방은 지시보다 직전 컨텍스트에 더 강하게 끌리기 때문이다. 대응안 1(훅 레벨 탐지)의 우선순위를 2(CLAUDE.md 규칙)보다 높게 두는 근거가 된다.

### 부수 관찰

- 10번에서 사용자의 `!` 명령이 **실행되지 않고 메시지 텍스트로만 전달된 케이스**가 2회 있었다. 사용자는 실행했다고 인지하는데 실제로는 아무 일도 일어나지 않는 상황이므로, 이것도 별도로 확인이 필요하다 (하네스 이슈일 가능성).
- 12번의 classifier 차단은 정상 작동했다. 훅이 뚫려도 한 겹이 더 있다는 뜻이지만, 15번 같은 **출력 서식 위조**는 classifier 관할 밖이다 — 도구 호출이 아니기 때문이다.
